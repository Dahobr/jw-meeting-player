# 設計ドキュメント：Electronプレイリストアプリ

**日付:** 2026-04-07

**トピック:** メディアダウンロードとZoom連携機能を備えたElectronプレイリストアプリケーション

## 1. 導入と目標

このドキュメントは、ユーザーがメディアプレイリストを作成、管理、再生できる新しいElectronアプリケーションの設計案を概説します。このアプリケーションは、指定されたJW.orgサイトからメディアをダウンロードするためのWebブラウジング機能、自動サムネイル生成、セカンドディスプレイでのシームレスな再生、および再生コンテンツの自動Zoom画面共有機能を提供します。ユーザーインターフェース全体はブラジルポルトガル語で表示されます。

## 2. ハイレベルアーキテクチャ

アプリケーションはElectronを使用して構築され、メインプロセスでウィンドウ管理、ファイルシステムアクセス、ダウンロードインターセプトなどのコア機能を利用し、レンダラープロセスでユーザーインターフェース（UI）を扱います。この分離により、堅牢性と効率的なリソース管理が保証されます。

## 3. 主要コンポーネント

### 3.1. メインウィンドウ (UI)
*   **言語:** ブラジルポルトガル語 (pt-BR)。
*   **レイアウト:**
    *   **ナビゲーションバー:** 「Cântico」、「Reuniões」、「Vídeos」の3つのボタンが含まれ、これらは埋め込みWebView内の特定のJW.org URLにリンクします。
    *   **プレイリスト管理エリア:**
        *   複数のプレイリストの作成、名前変更、削除をサポートします。
        *   選択したプレイリスト内の項目を表示し、並べ替え、名前変更、自動生成されたサムネイルの表示が可能です。
    *   **再生コントロール:** 専用の再生ウィンドウでのメディア再生を制御するため、メインウィンドウに配置されます（再生/一時停止、次項目、前項目、音量、フルスクリーン切り替え）。

### 3.2. WebViewコンポーネント
*   **目的:** メインウィンドウに埋め込まれ、指定されたJW.org URLへのナビゲーションを担当します。
*   **機能:** ユーザーがウェブサイトリンクをクリックしてメディアファイルをダウンロードする際のインターフェースとして機能します。

### 3.3. ダウンロードハンドラー
*   **メカニズム:** メインプロセスでElectronの `webContents.on('will-download')` イベントを利用し、WebView内で開始されたダウンロード要求をインターセプトします。
*   **ファイル検出:** WebView内のリンクのユーザークリックによって開始されたダウンロードを捕捉します。
*   **ファイル保存:** ダウンロードされたファイルは、固定のアプリケーション内部フォルダに自動的に保存されます。具体的なパスは確認が必要ですが、典型的な場所としてはユーザーのアプリケーションデータディレクトリ内（例: Windowsでは `%APPDATA%/ElectronPlaylistApp/downloads/`、macOSでは `~/Library/Application Support/ElectronPlaylistApp/downloads/`、Linuxでは `~/.config/ElectronPlaylistApp/downloads/`）が考えられます。
*   **プレイリスト連携:** 新しくダウンロードされたファイルは、現在のプレイリストに自動的に追加されます。
*   **ファイルタイプ:** MP4、JPG、PNG、GIF、BMP、WEBP、SVGをサポートします。
*   **エラーハンドリング:** ダウンロード失敗時には、「Não é possível fazer download ...」というメッセージを表示します。

### 3.4. サムネイル生成
*   **自動生成:**
    *   **MP4動画の場合:** 動画の約10秒時点のフレームを抽出します。
    *   **画像ファイル (JPG, PNG, GIF, BMP, WEBP, SVG) の場合:** 画像ファイル自体をサムネイルとして使用します。

### 3.5. 再生ウィンドウ
*   **目的:** メディア再生専用のウィンドウです。
*   **表示:**
    *   セカンドディスプレイがあればそこに表示されます。
    *   セカンドディスプレイが検出されない場合は、プライマリディスプレイにフォールバックします。
*   **動作:** 常に最大化され、最前面に表示されます。Zoomなどのアクティブなアプリケーションがフォーカスを奪った場合、再生ウィンドウが最前面にあるか定期的にチェックし、必要に応じて再配置するフォールバックロジックが実装されます。
*   **コントロール:** このウィンドウ内にはコントロールはありません（すべてのコントロールはメインウィンドウに配置されます）。
*   **メディアサポート:** MP4動画およびサポートされている画像フォーマットを再生します。
*   **エラーハンドリング:** 再生失敗時には、「N\xc3\xa3o \xc3\xa9 poss\xc3\xadvel reproduzir o arquivo ...」というメッセージを表示します。

### 3.6. Zoom連携モジュール
*   **トリガー:** メディア再生が再生ウィンドウで開始されると自動的に共有が開始され、再生が終了すると自動的に共有が停止します。
*   **方法:** Zoomの画面共有機能を制御するため、「Alt+S」キー操作をシミュレートします。
*   **共有コンテンツ:** 再生ウィンドウのコンテンツ（動画および画像）。

## 4. ユーザーフロー

### 4.1. プレイリストの作成
1.  ユーザーはメインウィンドウの「プレイリスト作成」ボタンをクリックします。
2.  ユーザーは新しいプレイリストに名前を付けます。

### 4.2. メディアのダウンロードと追加
1.  ユーザーはメインウィンドウのナビゲーションボタン（Cântico, Reuniões, Vídeos）のいずれかをクリックします。
2.  指定されたJW.org URLが埋め込みWebViewで読み込まれます。
3.  ユーザーはサイトを閲覧し、画像または動画のダウンロードリンクをクリックします。
4.  `will-download` イベントがトリガーされます。
5.  ダウンロードハンドラーはファイルを固定アプリケーション内部フォルダに保存し、現在のプレイリストに追加します。
6.  新しく追加された項目に対してサムネイル生成が行われます。

### 4.3. メディアの再生
1.  ユーザーはメインウィンドウのプレイリストから項目を選択します。
2.  再生マネージャーが専用の再生ウィンドウで再生を開始します。
3.  再生ウィンドウは最大化され、セカンドディスプレイ（またはプライマリディスプレイ）に表示され、最前面に留まります。
4.  Zoom連携モジュールは、再生開始をトリガーとして、Alt+Sキー操作により再生ウィンドウのコンテンツの共有を自動的に開始します。
5.  ユーザーはメインウィンドウのコントロールを通じて再生を制御します（再生/一時停止、次へなど）。
6.  再生が停止すると、Zoom連携モジュールは自動的に共有を停止します。

## 5. 今後の検討事項 / 未解決のポイント

*   **固定フォルダのパスの具体性:** ユーザーのアプリケーションデータディレクトリ内へのデフォルトパスを提案しますが、具体的なパスの確認が必要になる場合があります。
*   **ダウンロード検知のニュアンス:** メディアファイルタイプ（MP4、画像フォーマット）とその他のダウンロードをフィルタリングする必要があるか検討が必要です。
*   **動画サムネイル抽出の詳細:** 約10秒時点のフレームを抽出する正確な方法について、実装上の詳細を定義する必要があります。
*   **再生ウィンドウの常時最前面ロジック:** Zoomのようなフォーカスを積極的に奪うアプリケーションを処理し、再生ウィンドウが常に最前面にあることを保証するための、より洗練されたメカニズムの詳細設計が必要になります。
